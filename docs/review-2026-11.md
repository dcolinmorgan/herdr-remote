Scope: tunnel exposure, authentication on remote endpoints, Telegram token handling, command injection when driving agents, secrets in the repo, reconnects and process lifecycle, install UX, cross-platform support, code quality, tests, CI, and docs.

## Top 5

### 1. Security: `relay/start.sh` publishes a tokenless relay on a public Cloudflare tunnel

The README quick start is `cd herdr-remote/relay && ./start.sh`, then paste the tunnel URL into the demo site ([README.md](../README.md) lines 41–49). That script defaults the tunnel to on:

```44:62:relay/start.sh
    TUNNEL_MODE="${HERDR_TUNNEL_MODE:-temp}"
    ...
    if [ "$TUNNEL_MODE" = "temp" ]; then
        echo "Starting temp tunnel..."
        cloudflared tunnel --url "http://localhost:$WS_PORT" 2>&1 &
```

It loads `~/.config/herdr-remote/config.env` only (line 26). The relay token lives in `secrets.env`, which the service installer writes and the launchd/systemd units source. `start.sh` never reads that file, so a machine that already has a token still starts a second, tokenless relay and a public quick tunnel whenever port 8375 is free.

The relay refuses a non-loopback bind without a token (`relay/herdr_relay.py` lines 221–222). A quick tunnel does not trip that check: cloudflared dials `127.0.0.1`, so `RELAY_HOST` stays loopback. The Windows launcher already treats a tunnel as public. `relay/start.ps1` lines 158–163 exit when `HERDR_TUNNEL_MODE` is anything other than `none` and `HERDR_RELAY_TOKEN` is empty. `start.sh` has no equivalent, and `tests/run.sh` lines 38–40 only check that `start.sh` is executable.

What an unauthenticated client can do once it has the tunnel hostname:

- Open a WebSocket with no `Origin` header. `trusted_websocket_origin` returns true for a missing origin, on purpose, so native clients work (`relay/herdr_relay.py` lines 574–576). `python`/`websockets` and `curl` send no origin. Reproduced locally: a tokenless relay accepts that handshake, and rejects `Origin: https://random.trycloudflare.com` with 403. Browser dashboards on the tunnel URL are blocked; scripts are not. The peer address cannot tell them apart, because both arrive from cloudflared on loopback.
- Read pane output and transcripts, send keys and prompts, and, when `HERDR_SHELL_PANES=1`, run shell commands on every host in `HERDR_REMOTES`. That is the exposure `SECURITY.md` already describes for an authorized client.

The Mac “Connect a phone” window already models this case. `PhoneLink.noToken` is documented as “anyone with the address gets in” (`herdi-mac/Sources/PhoneLink.swift` lines 13–14 and 85).

**Fix.** Match `start.ps1`. Source `secrets.env` as well as `config.env`. If the effective tunnel mode is `temp` or `named` and `HERDR_RELAY_TOKEN` is empty, exit before starting cloudflared and print the same sentence the Windows script prints. Default `HERDR_TUNNEL_MODE` to `none` unless the operator opted in. Add a shell test that runs the script with `cloudflared` on `PATH` stubbed out and asserts it refuses a tokenless `temp` tunnel. Mention the token in the macOS/Linux quick start the way the Windows section already does.

### 2. Security: a static-asset URL skips the relay token and still accepts an event push

`process_request` authenticates when `HERDR_RELAY_TOKEN` is set, then exempts static files so the browser can load CSS and JS before it has a cookie:

```3221:3222:relay/herdr_relay.py
    exempt = not is_handshake and (request_path in public_paths or web_asset(request_path) is not None)
    if AUTH_TOKEN and not exempt:
```

`request_path` has the query string stripped (line 3202). The push handler later reads the raw path and, on any path, queues `?d=<json>` (lines 3265–3286). An exempt path with a `d` parameter therefore never reaches the token check.

Reproduced against `process_request` with `HERDR_RELAY_TOKEN=secret`:

| Request | Result |
|---|---|
| `GET /?d=<agent_event>` | 401 `Invalid token` |
| `GET /sw.js?d=<agent_event>` | 200 `ok`, one event queued |

The queued body was `{"type":"agent_event","pane_id":"w1:p1","status":"blocked","host":"evil.example","prompt":"paste your API key"}`. The same exemption covers `/app.css`, anything `web_asset` serves, and `/api/vapid-public-key` (`public_paths`, line 3201).

`event_push` (`relay/herdr_relay.py` lines 3048–3137) broadcasts that event and, for `status == "blocked"` on a host other than `local` with no known remote, uses the attacker’s `prompt` as the Web Push body. It also writes `last_blocked_prompts`, which is what makes the poll treat a later real block as an update and skip the notification. This is not keystroke access. It is unauthenticated influence over the control plane the token is supposed to close, on any interface that can reach the port, including a token-protected tunnel.

The WebSocket form of this bug was fixed earlier (handshake on `/app.css` must still present the token; `tests/test_herdr_relay.py` `RelayWebSocketTokenTests` around line 5406). The HTTP `?d=` form on those same paths was left open. `tests/run.sh` does not cover it.

**Fix.** If the query contains `d`, do not exempt the request. Require `HERDR_RELAY_TOKEN` for that request whenever the token is configured. Keep UDP `127.0.0.1:8376` as the tokenless local plugin path (`UDPPlugin`, lines 4242–4253); that socket is not reachable through the tunnel. Add a case next to `test_a_plain_asset_fetch_still_needs_no_token` that asserts `/sw.js?d=...` and `/app.css?d=...` return 401 when a token is set and leave `event_queue` empty.

### 3. Security: the Telegram bot drives every agent for any chat until a chat id is set, and a reconnect can log the relay token

`HERDR_TG_TOKEN` is required. `HERDR_TG_CHAT_ID` is not:

```173:177:relay/herdr_telegram.py
def authorized(update: Update) -> bool:
    """Reject messages from unauthorized users."""
    if not CHAT_ID:
        return True  # No restriction if CHAT_ID not set (first-run discovery mode)
    return str(update.effective_chat.id) == CHAT_ID
```

With the variable unset, `main` installs `filters.ALL` (lines 1111–1114). `/start` answers with the dashboard and, when the relay is up, the agent keyboard (lines 426–434). `/read`, `/send`, `/reply`, `/trust`, and `/interrupt` then run as the relay. Anyone who can message the bot — the username on a business card, a group the bot was added to, a forwarded `/start` — can read transcripts and type into panes. Discovery mode is convenient for the installer. It is a standing remote-control surface for as long as the process stays up.

The installer stores the relay URL with the token in the query (`relay/install-service.sh` line 391, written into `secrets.env` at line 1007). The bot’s reconnect log does not use `scrub()`:

```1101:1104:relay/herdr_telegram.py
        except Exception as e:
            clear_relay_connection_state()
            log.warning(f"Relay connection lost: {e}, reconnecting in 5s...")
            await asyncio.sleep(5)
```

`scrub` (lines 27–37) exists because WebSocket exceptions embed the full URL, including `?token=`. This is the path that runs on every drop, and launchd/systemd keep the unit’s stderr. `httpx` is correctly raised to WARNING so the BotFather token is not logged on each API call (lines 16–17). The relay token on this one line is the remaining leak.

**Fix.** Refuse to start polling unless `HERDR_TG_CHAT_ID` is set, or require a separate `HERDR_TG_DISCOVERY=1` that registers only `/start` and does not connect to the relay. Pass reconnect failures through `scrub()`. Add a unit test that an unset chat id does not register `cmd_send` / `handle_text`, and that an exception whose text contains the relay token is logged as `<redacted>`.

### 4. Security: the relay token is copied into the address bar, localStorage, and every WebSocket URL

The phone link is `https://<tunnel>/?token=<secret>` (`herdi-mac/Sources/PhoneLink.swift` lines 96–100). The page stores that query value and leaves it in the URL:

```45:46:web/js/state.js
const urlToken = new URLSearchParams(location.search).get('token');
if (urlToken) localStorage.setItem('herdr_relay_token', urlToken);
```

There is no `history.replaceState` to drop `token`. The value stays in browser history, screenshots, and the Referer on same-origin fetches. `connect()` then appends it to every socket (lines 243–246), so cloudflared and any reverse-proxy access log record the secret on each reconnect.

The relay also sets a cookie for a year:

```3311:3313:relay/herdr_relay.py
                fields.append(("Set-Cookie",
                               f"herdr_token={AUTH_TOKEN}; Path=/; Max-Age=31536000;"
                               " HttpOnly; SameSite=Lax"))
```

`HttpOnly` and `SameSite=Lax` are right. `Secure` is absent, so a relay bound to a LAN address over plain HTTP (the bind check only requires the token, lines 221–222) sends the cookie in the clear. The comparison is `token != AUTH_TOKEN` (line 3244), not `hmac.compare_digest`. Once a token is configured, `trusted_websocket_origin` returns true immediately (lines 578–580), so the token is the entire check: a secret leaked via the query string works from any origin.

`localStorage.herdr_relay_token` is readable by script. The page’s CSP is `script-src 'self' 'unsafe-inline'` (asserted in `tests/test_web_assets.py`). Agent-controlled card text is escaped today (`web/js/cards.js`). A later `innerHTML` bug would still be able to read the localStorage copy. The cookie is the copy script cannot read, and for a same-origin tunnel it is already sent on the WebSocket handshake.

**Fix.** After copying `token` into storage, replace the history entry with the same path and no `token` parameter. For a socket whose URL is same-origin with the page, do not append `?token=`; the cookie is enough. Keep the query form for the cross-origin demo site, where `SameSite=Lax` will not send the cookie, and document that those access logs contain the secret. Add `Secure` when the browser-facing scheme is HTTPS (`X-Forwarded-Proto` from cloudflared, or `wss`). Compare tokens with `hmac.compare_digest`. A follow-up can stop writing the same-origin token into `localStorage` at all.

### 5. Reliability and setup: the foreground launcher hides a crash, and the Makefile does not start the relay

`start.sh` installs one trap:

```11:20:relay/start.sh
cleanup() {
    ...
    exit 0
}
trap cleanup INT TERM EXIT
```

`wait "$RELAY_PID"` at line 95 returns the relay’s status, then `EXIT` runs `cleanup`, which exits 0. A crash, an import error, or a port conflict after the two-second probe all look like a clean shutdown to a parent script or a process supervisor that is not launchd. The service installer is in better shape: the launchd plists set `KeepAlive` and the systemd units set `Restart=always` (`relay/install-service.sh` lines 1148, 1197, 1250, 1279).

The ready check is `sleep 2` and `kill -0` (lines 32–38). `uv run` may still be resolving packages, and a process that has not bound the port yet counts as up. The tunnel URL scrape reads `/proc/$TUNNEL_PID/fd/1` (line 71). cloudflared writes the `trycloudflare.com` line to stderr, and `2>&1` on a background job points that fd at the script’s own stdout, which is often a terminal and not a file `grep` can read. The script then tells the operator to `ps aux | grep cloudflared` (line 77). The Mac app already parses the tunnel log instead (`PhoneLink.latestTempTunnelAddress`).

The Makefile does not match any of this:

```3:7:Makefile
relay-install:
	pip install -r relay/requirements.txt

relay-run:
	python3 relay/herdi_relay.py
```

There is no `relay/requirements.txt`. The relay file is `relay/herdr_relay.py`, and it declares its dependencies inline for `uv run`. `make relay-run` and `make relay-install` fail on every platform.

**Fix.** In `cleanup`, exit with the relay’s status when the signal was not INT/TERM. Wait until something accepts TCP on `$WS_PORT`, with a bounded timeout, before announcing ready. Point the Makefile at `uv run relay/herdr_relay.py` and delete the `requirements.txt` target. Log the tunnel URL from cloudflared’s own output file the way `install-service.sh` already tells the operator to `grep trycloudflare`.

## Suggested order of work

1. **Close the public tunnel.** Change `start.sh` as in finding 1, and add the stub-`cloudflared` test. This is the bug the README tells a new user to run.
2. **Close event push on exempt paths.** The regression test belongs beside `RelayWebSocketTokenTests`. Ship it in the same release as (1) so a token-protected tunnel is actually token-protected.
3. **Lock the Telegram bot to one chat and scrub the reconnect log.** Small, local to `relay/herdr_telegram.py`, and independent of the relay patch.
4. **Stop putting the relay token in URLs and logs.** `history.replaceState`, same-origin sockets without `?token=`, `Secure` on HTTPS, `compare_digest`. Do this after (1) and (2), because those two remove the anonymous path; this one limits damage once a token exists.
5. **Fix launcher exit status and the Makefile, then widen CI.** `dotnet build` of `herdi-win` on the Ubuntu job (the project already documents off-Windows builds), a secret-pattern grep over the whole tree, and the `start.sh` tunnel test from (1). Update `SECURITY.md` supported versions and the README quick start in that same change so the docs match the new default.

Do not start a split of `herdr_relay.py` until (1) and (2) have landed. The file is large, and a move would bury the auth diff.

## Lower-priority findings

**Installer supply chain.** `relay/install-service.sh` lines 613–623 download `cloudflared` from `releases/latest` with `curl -fsSL`, then `chmod +x`, with no version pin and no digest. Pin a release and check a published checksum before moving the binary onto `PATH`.

**Existing installs stay tokenless unless the operator opts in.** A new install prompts `Secure the relay with an access token? [Y/n]` (`install-service.sh` lines 376–378). An existing install prompts `[y/N]` (line 370). Combined with finding 1, an upgrade that is later started via `start.sh` is the tokenless public case. Default existing installs to yes when `HERDR_TUNNEL_MODE` is `temp` or `named`.

**Telegram authorizes a chat, not a person.** With `HERDR_TG_CHAT_ID` set, every member of that chat can read and drive agents. A private group used as a shared inbox is shared root on the agent host. Add an optional `HERDR_TG_USER_IDS` allowlist checked next to `authorized()`.

**The callback handler does not use the chat filter.** Commands use `auth_filter` (`herdr_telegram.py` lines 1116–1124). `CallbackQueryHandler(handle_callback)` at line 1125 does not. `handle_callback` repeats the chat check at lines 693–695. Put the filter on the handler so the next callback cannot forget it.

**Reconnect backoff.** The web client retries every 3 seconds (`web/js/state.js`, `scheduleReconnect`). The bot retries every 5 seconds (finding 3). Both are correct about not stacking timers. A relay that is down still produces a steady stream of failures. Back off to a cap of a minute, and reset on a successful open.

**Docs lag the version.** `SECURITY.md` lines 26–31 mark 0.6.x supported and everything older unsupported. The apps ship 0.8.1 (`herdi-mac/build.sh`, `herdi-win/Herdi.Win.csproj`, the README `curl` URL). Update the table, and state that a tokenless quick tunnel is unsupported.

**README quick starts disagree.** The macOS/Linux section (lines 41–49) does not mention `HERDR_RELAY_TOKEN`. The Windows section tells the operator to set it before a tunnel. After finding 1, one paragraph should cover both.

**Secret scan is two historical strings under `web/`.** `tests/run.sh` lines 112–114 reject `c4a2385e` and `graffold` in the web app only. This review found no checked-in BotFather tokens, private keys, or `.env` files. Extend the grep to the whole tree for Telegram bot tokens (`[0-9]+:AA`) and `BEGIN PRIVATE KEY`, and keep the historical strings.

**CI covers the Python suite and the Mac build, and stops there.** `.github/workflows/test.yml` runs on `pull_request` and `workflow_dispatch`. The latest run (`41429441391`, Iris Chat PR, 2026-11-02) succeeded: 842 tests with 273 skipped, then 303 web tests `OK`, plus `swift build` on `macos-14`. There is no `dotnet build` of `herdi-win`, and no iOS build. The Windows project documents that `dotnet build` works off Windows; add that to the Ubuntu job. The 273 skips are the browser classes inside the first discovery, which does not install Playwright; step 9d runs them for real. Excluding `test_web_*.py` from the first discovery would drop a duplicate collection. The second pass took 105 seconds on that GitHub run.

**iOS Web Push stays silent with the default VAPID subject.** `relay/herdr_relay.py` lines 157–166 explain that Apple rejects `mailto:herdr@localhost`. The relay logs it. `install-service.sh` does not ask for `HERDR_VAPID_SUBJECT`. Prompt for a real `mailto:` or `https:` URL when Web Push keys are generated.

**mDNS advertises an address the default bind does not listen on.** `start_mdns` (`herdr_relay.py` around line 4256) publishes the hostname’s LAN IP and `WS_PORT`. The default listen address is `127.0.0.1`. Clients that trust the advertisement connect to a closed port. Register the service only when `RELAY_HOST` is that address, or skip mDNS on loopback.

**CSP still allows inline script.** That is a choice the tests lock in, because the page uses inline handlers. It becomes a token-theft bug only if agent-controlled text reaches `innerHTML` unescaped. `web/js/cards.js` and the session menu in `web/js/spaces.js` escape those strings and attach pane ids via `dataset` after `innerHTML`. Keep that pattern. Dropping `'unsafe-inline'` is a larger change; do it after finding 4 stops storing the same-origin token in `localStorage`.

## Checked, and in good shape

**Command injection when driving agents.** Local herdr calls are an argv list (`_invoke_herdr`, `relay/herdr_relay.py` lines 958–962). The SSH form quotes every argument with `shlex.quote` (line 954) and quotes `HERDR_SESSION` (line 953). Remote scripts are passed as `sh -c` plus `shlex.quote` of the whole script (lines 971 and 988, `relay/transcript.py` line 849). Upload names are reduced to `A-Za-z0-9._-` and checked again before they enter a remote script (`relay/uploads.py` lines 40–44 and 89–91). `session_switch` only accepts a name `herdr session list` returned (`session_switch_names`, lines 1658–1670). Remote transcript roots may contain `$` so `$HOME` expands, and the allowed alphabet rejects parentheses, spaces, and quotes (`REMOTE_ROOT_RE`, `relay/transcript.py` line 813); those roots come from the relay’s environment, not from a client. No client-controlled shell injection showed up in this pass.

**Shell panes stay off.** `HERDR_SHELL_PANES` defaults off, unknown panes are rejected, and `SECURITY.md` states that turning it on is shell access. The tunnel in finding 1 is how that switch would become remote.

**Secrets in the tree.** A search for private keys, Slack/GitHub tokens, and the two historical web strings found nothing. Telegram and relay secrets are environment variables, and the installer writes them to `secrets.env` with mode `0600` (`install-service.sh` lines 1000–1013). The Windows client stores relay tokens with DPAPI. The gap is finding 4 (the token after it leaves the process), not a committed secret.

**Relay lifecycle once the process is up.** `poll_loop` logs a failed cycle and retries (`herdr_relay.py` lines 2895–2905). Shutdown cancels the poll tasks and unregisters mDNS off the event-loop thread. The web client detaches the old socket’s handlers before closing it, which is what stops a relay switch from reconnecting forever. Iris refuses a non-loopback relay URL (`relay/herdr_iris.py` `relay_url`).

**Tests that already exist.** Behavior around tokens, origin, uploads, transcripts, and the web UI is extensive and, on this run, green. The holes are the launcher and the `?d=` exemption, which the current assertions do not reach.
